# VPg04 RAG

Telegram-бот с RAG-агентом. Перед ответом ищет фрагменты в Pinecone, умеет запоминать факты о пользователе, читать HTML-страницы и делать GET к публичным API.

Чат-модель — OpenAI или совместимый прокси (`OPENAI_BASE_URL`). Текст режется на фрагменты по 1000 символов с перекрытием 200.

## Состав

| Файл | Назначение |
| --- | --- |
| `main.py` | Запуск Telegram-бота |
| `bot.py` | Команды и сообщения PyTelegramBotAPI |
| `rag_agent.py` | Поиск, запись, чтение страниц, GET к API |
| `rag_agent.py` как модуль | Проверка связи с Pinecone без чата |
| `.env.example` | Список переменных окружения |

## Подготовка

Нужен Python 3.11+ и уже созданный индекс Pinecone.

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`. Файл с ключами не коммитьте.

```text
OPENAI_API_KEY=
OPENAI_BASE_URL=
OPENAI_MODEL=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
PINECONE_API_KEY=
PINECONE_INDEX_NAME=
PINECONE_NAMESPACE=
TELEGRAM_BOT_TOKEN=
```

`OPENAI_BASE_URL` необязателен. Если он задан, и чат, и эмбеддинги ходят через этот адрес. Токен бота выдаёт [@BotFather](https://t.me/BotFather).

Индекс может быть двух видов. Код выбирает способ сам по описанию индекса:

- Документный индекс с полем `embed` (в этом проекте это `chunk_text`). Текст пишет и ищет Documents API Pinecone, эмбеддинг считает сам Pinecone.
- Обычный векторный индекс. Текст эмбеддит OpenAI. Если размерность индекса меньше родной размерности модели `text-embedding-3-*`, вектор укорачивается.

`PINECONE_NAMESPACE` можно оставить пустым. Для документного индекса тогда используется `__default__`.

## Запуск

Один процесс на один токен. Второй опрос того же бота конфликтует с первым.

```powershell
.\venv\Scripts\python.exe main.py
```

Проверка, что индекс отвечает на поиск. Пустой результат тоже считается успехом: важно, что запрос дошёл.

```powershell
.\venv\Scripts\python.exe rag_agent.py
```

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Краткая справка |
| `/add текст` | Сразу пишет текст в базу. Без текста бот ждёт следующее сообщение |
| `/read https://пример.com` | Читает HTML, режет на фрагменты и сохраняет. После ссылки можно задать вопрос |
| `/cancel` | Отменяет ожидание текста или ссылки |

Обычное сообщение — это вопрос. Перед ответом бот ищет фрагменты и факты этого пользователя.

Примеры без команд:

- «Меня зовут Анна» или «запомни, что я люблю чай» — факт сохраняется в память пользователя.
- «Добавь в базу: …» — текст сразу попадает в базу знаний.
- «Какая погода в Сочи?» — GET к Open-Meteo. В чат уходит температура и описание, а не сырой JSON.
- Ссылка на публичный API в вопросе — GET по этому адресу, ответ строится по телу.
- «Прочитай https://…» — страница сохраняется как HTML. Это не то же самое, что запрос к API.

Пароли, токены и ключи бот не сохраняет. Ссылки на localhost и внутренние адреса не открываются.

## Ошибки, которые уже встречались

Википедия часто отвечает `403` на запрос бота. Тогда страница не попадёт в базу, и бот сообщит об ошибке чтения.

`vector_upsert_failed` на документном индексе значит, что запись ушла в старый векторный API. Текущий код для такого индекса пишет документы в поле `chunk_text`. После смены кода процесс `main.py` нужно перезапустить.
